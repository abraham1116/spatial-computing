Security

What the prototype protects, and what it does not protect yet.

In place

  • Loopback by default. Binding another address raises PermissionError unless --allow-remote is passed: an explicit act by the machine's owner.
  • Authentication. A random 32-byte token (file mode 600) and an HMAC-SHA256 challenge-response; a wrong token is dropped without a reply.
  • No code transmitted. The worker only runs named workloads from an allow-list.
  • Closed micro-VM. No network device, no disk, no host folder; RAM capped.
  • Quota on the page server's memory.

Not in place yet

  • Channel and page encryption before sending: route it through TLS or WireGuard before any use beyond loopback.
  • Per-user or per-tenant permissions, CPU quotas, a signed log.
  • A sandbox for arbitrary third-party workloads.
Do not exposeDo not use --allow-remote on a network you do not control: the channel is not encrypted.

To report a vulnerability, use GitHub's private vulnerability reporting on the repository.
