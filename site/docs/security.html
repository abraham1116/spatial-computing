Security

What the prototype protects, and what it does not protect yet.

In place

  • Loopback by default. Binding another address raises PermissionError unless --allow-remote is passed: an explicit act by the machine's owner.
  • Authentication. A random 32-byte token (file mode 600) and an HMAC-SHA256 challenge-response; a wrong token is dropped without a reply.
  • No code transmitted. The worker only runs named workloads from an allow-list.
  • Closed micro-VM. No network device, no disk, no host folder; RAM capped.
  • Quota on the page server's memory.
  • Encrypted, forward-secret channel. Every record is sealed with AES-256-GCM; keys come from an ephemeral X25519 exchange mixed with the secret, so a recorded session stays unreadable if the secret leaks later. A modified or replayed record is rejected.
  • Scoped permissions. A server started with a master key issues credentials with scopes (run:mandel_numba, mem:read, exec:elf), an expiry and quotas; every request, allowed or denied, goes to the audit log.
  • Encrypted and replicated far pages with EncryptedBackend and ReplicatedBackend.
  • Tamper-evident ledger. Measurements are hash-chained; Ledger.verify() finds an edited row.

Not in place yet

  • An independent security review. None has been done.
  • Certificate-based identity (the secret is the identity), a signed audit log, revocation and usage counters that survive a restart.
  • A sandbox for arbitrary third-party workloads.
Do not exposeDo not use --allow-remote on a network you do not control: the protocol has had no independent review.

To report a vulnerability, use GitHub's private vulnerability reporting on the repository.
