REST API

Everything the console does, for scripts.

The console's REST API is what the console itself uses. Base URL: your console (for example http://127.0.0.1:8090). Bodies and answers are JSON. Errors: {"error": "message"} with the HTTP status (400 bad input, 401 not signed in, 402 budget reached, 403 refused, 404 not found or not yours, 409 conflict, 429 too many attempts).

Authentication

  • Browser session: POST /api/login sets an HttpOnly cookie; send the csrf value it returns in an X-CSRF-Token header on every POST, PATCH and DELETE.
  • Account token (scripts): create one in Settings, then Authorization: Bearer spt_…. No cookie, no CSRF. A read token may only GET. Tokens cannot create tokens, change the password, delete the account or list sessions.
curl -H "Authorization: Bearer $TOKEN" http://127.0.0.1:8090/api/apps
curl -X POST -H "Authorization: Bearer $WRITE_TOKEN" -H "Content-Type: application/json" \
     -d '{"name":"batch"}' http://127.0.0.1:8090/api/apps

Example: from nothing to a result

# with a write token
APP=$(curl -s -X POST -H "Authorization: Bearer $T" -H "Content-Type: application/json" -d '{"name":"demo"}' $BASE/api/apps | jq .app.id)
curl -s -X POST -H "Authorization: Bearer $T" -H "Content-Type: application/json" -d '{"name":"n","kind":"node"}' $BASE/api/apps/$APP/keys | jq -r .key.token > node.tok
spatial agent --hub HUB:7700 --token-file node.tok &
curl -s -X POST -H "Authorization: Bearer $T" -H "Content-Type: application/json" \
     -d '{"workload":"montecarlo_pi","params":{"samples":1000000}}' $BASE/api/apps/$APP/jobs
LimitsNo pagination and no webhooks to you (usage is polled), no per-token rate limit, one unversioned API surface that may change. Tested through HTTP in tests/test_platform.py.
