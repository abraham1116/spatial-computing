Tiered memory

Address more data than the local RAM budget, trading RAM for CPU and latency.

This is not RAMThe compressed tier costs CPU. The far tier costs latency. The far_memory type is distinct from ram throughout the code, and a test enforces it.

The three tiers

TierContentCost
HotUncompressed pages in RAM, LRUNone
CompressedCompressed (LZ4 or zlib-1) and deduplicated pages in RAMCompression CPU
FarFile on SSD or a remote page serverAccess latency

Usage

from spatial.memory import TieredStore, FileBackend

st = TieredStore(hot_bytes=16 << 20, compressed_bytes=16 << 20,
                 far=FileBackend("/tmp/far.bin"),
                 prefetch=16, keep_far_copy=True)
st.put(0, page_bytes)
st.get(0)
print(st.stats())

stats() always separates logical bytes from bytes actually held in local RAM, and gives per-tier hit ratio and latency (mean or p50/p99).

Measured optimizations

  • Read-ahead on sequential-scan detection.
  • Keeping the far copy of an unmodified page: its next eviction costs no write.

On an emulated 0.2 ms link, a sequential scan goes from 2,605 to 2,047 µs per access with read-ahead, then to 1,305 µs with the far copy kept.

Limits

A Python library used through an API: not transparent kernel paging, and macOS offers none in user space. Single writer, no encryption or replication of far pages. The LAN and WAN links in the benchmarks are emulated.
