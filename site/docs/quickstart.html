Quickstart

From zero to a first job. Two ways: the console (accounts, keys, jobs) or the command line alone.

Fastest path: the console

  1. Open the console (http://127.0.0.1:8090 if you run it yourself, see Console and accounts) and create an account.
  2. On the Overview, press New app, then create a node key and a client key (API keys). Each is shown once: save it.
  3. On a machine: pip install spatial-computing, then spatial agent --hub HUB:7700 --token-file node.tok. It appears in Fleet.
  4. Open Jobs, pick montecarlo_pi, submit. See the result, the usage and the estimated charge in Usage & billing.

Prefer scripts? The same steps are in the REST API.

Command line only

Python 3.10 or newerTested on macOS 13 (Intel) with Python 3.13, and in CI on Linux and macOS.
On PyPIPublished as spatial-computing. To work on the code itself, clone the GitHub repository and run pip install -e ".[dev]".

1. Environment

python3 -m venv .venv && source .venv/bin/activate
pip install spatial-computing

numpy (< 2.2) and numba (< 0.62) are bounded: newer Numba needs an llvmlite that does not build on the reference Mac.

2. Verify

spatial audit
spatial status
pytest

3. Linux micro-VM (optional)

The microvm route of the Runtime Engine needs QEMU (for example sudo port install qemu with MacPorts) and two files downloaded once into vendor/, checked by SHA-256.

mkdir -p vendor && cd vendor
curl -O https://dl-cdn.alpinelinux.org/alpine/v3.22/releases/x86_64/netboot/vmlinuz-virt
curl -o busybox-x86_64 https://busybox.net/downloads/binaries/1.35.0-x86_64-linux-musl/busybox
shasum -a 256 -c SHA256SUMS

4. Test binaries (optional)

To reproduce the runtime tests, install the build extra (the ziglang cross-compiler) and run spatial bench runtime: it compiles the same C program for macOS, Linux, Windows and WASM into benchmarks/build/.
