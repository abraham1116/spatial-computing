Planner

One objective for every engine: get each job done correctly at the lowest cost, and prove it.

The objectiveGet the job done correctly at the lowest cost in dollars, within the constraints you state (deadline, RAM, isolation, hardware allowed), and prove it: the estimate is recorded next to what really happened, and future estimates are corrected by that history.

How the engines fit together

Each engine has a provider that turns a job into priced options. One function ranks them. One ledger records the decision and, after execution, the measurement.

EngineOptions it proposes
ComputeEach variant of a numerical or batch-scoring job (e.g. pure Python, NumPy, Numba, multi-core, or a portable kernel on CPU/Metal), probed on reduced problems and checked against the others
FleetThe same job on each live node, at the node's own price per hour
Accelerator fabricThe same job on the CPU, a Metal GPU or an NVIDIA GPU (the NVIDIA path is written, never run on real hardware); on the reference Mac the planner picked the faster device in 7 of 7 sizes
Portable kernelsOne kernel source, run on the CPU or a Metal GPU (CUDA C is generated, never run); the integer kernel is bit-identical on both; device choice right in 4 of 6 cases, misses at the crossover
Virtual interconnectEncrypted all-reduce between workers (ring, halving-doubling, tree), algorithm chosen by a measured cost model; on one machine it is about 3,000 times below NVLink 5 on bandwidth, so it is a software layer, not a replacement
Tiered memoryA dataset in RAM or tiered over SSD, with tier latencies measured on this machine
RuntimeEvery route for a binary (native, WASM, micro-VM, Wine) with its isolation and overhead
AIA cached prefix: recompute, or keep and restore it

Use it

spatial optimize compute --family pk_batch_score --params '{"n":512,"signals":16}' --execute
spatial optimize dataset --gib 24 --accesses 200000 --max-ram-gib 2
spatial optimize kv --prefix-tokens 2000 --reuse 0.8 --execute
spatial optimize binary --file app.elf --isolated 64 50

Is the decision good?

Every feasible option was run for real and timed, then compared with the planner's choice (one machine, one price per hour, so cheapest = fastest).

EstimatorCasesPicked the fastestMedian estimate error
Single probe1310 (77 %)28 %
Two sizes, affine fit1310 (77 %)16 %
+ best of several probes1312 (92 %)7 %
Same, on 12 cases never used while tuning1212 (100 %)5 %

The first versions mis-ranked the multi-core variant on mid-size jobs because microsecond probes were dominated by thread start-up noise; keeping the best of several runs fixed it.

LimitsOne machine, 25 cases, numerical kernels, predating the removal of the quantum and scientific-simulation engines. Estimates are per machine (the planner re-probes each time). Calibration is a median of past ratios, not a learned model. Dollar costs use the prices you give: the default local price (0.134 $/h) is an assumption, and a fleet node without a price is rejected. The AI engine is a toy model. Details: docs/OBJECTIVE.md.
