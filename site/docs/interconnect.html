Interconnect

Collective operations between workers over the encrypted channel, with the algorithm chosen by a measured cost model.

Not an NVLinkNVLink is silicon and copper. This is a software layer over whatever link exists. On the reference machine its best bus bandwidth is about 0.2 to 0.3 GB/s; NVLink 5 is quoted at 900 GB/s per direction (vendor figure), about 3,000 to 4,000 times faster.

What it does

spatial.interconnect runs N processes that exchange data through SWP/2 (AES-256-GCM, forward-secret). It provides ring, halving-doubling and tree all-reduce, and broadcast. A cost model t = α + M/β predicts the time of each algorithm; allreduce(..., algo="auto") takes the cheapest.

AlgorithmPredicted time (M bytes, N ranks)Good for
ring2(N−1)α + 2(N−1)/N · M/βlarge messages
halving-doubling2·log₂N·α + 2(N−1)/N · M/β (N a power of two)medium messages
tree2·log₂N·(α + M/β)small messages

Measured

  • All algorithms return the exact sum (tests).
  • Fitted link on loopback: α ≈ 150 to 200 µs per message, β ≈ 650 to 740 MB/s.
  • The single shared link model chose the fastest algorithm in 1 of 6 sizes at N = 4, 8 and 16 (4 of 6 at N = 6). It always preferred halving-doubling; in practice tree won for small messages and ring for large ones.
  • Calibrating each algorithm separately fixes most of it: judged on a rank count it had not seen, 3 to 5 of 6 right, mean regret 1.07× to 1.27×. Results move from one run to the next, so read the trend, not one count.

Limits

One machine, loopback, N = 4, 6, 8, 16 as processes on two cores (this measures CPU contention as much as a link). No RDMA, no GPU memory, no fault tolerance. NCCL, MPI, UCC and MSCCL++ are mature: the value here is a cost-model-driven, encrypted, hardware-neutral layer that feeds the same planner. Details: docs/INTERCONNECT.md.
