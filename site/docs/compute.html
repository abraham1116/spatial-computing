Compute Engine

Detects the hardware, measures its usage, compares execution strategies and picks the best one.

Detect and monitor

spatial audit reads the real hardware (model, cores, SIMD instruction set, GPU, RAM, swap, storage) and the current state: memory pressure, macOS compressor ratio, idle resources, then lists the limits that follow.

Compare strategies

The ComputeScheduler runs each strategy on a reference computation, measures duration, CPU time and peak memory, and rejects any result that differs from the reference. Strategies for the demo workload: pure Python, NumPy, Numba JIT, Numba multi-thread, cold and warm process pool, remote worker, local + worker distributed.

from spatial.compute import detect_node
from spatial.compute.scheduler import ComputeScheduler

sched = ComputeScheduler(detect_node())
rows = sched.compare("exp", {"n": 4000, "iters": 300}, sched.mandel_strategies())
best = sched.choose(rows, objective="time")   # "time" | "cpu" | "energy"

Offload to a worker

The worker only runs named workloads from an allow-list: no code is transmitted. It listens on 127.0.0.1 and requires a token (HMAC).

python3 -c "import os;open('token','wb').write(os.urandom(32))" && chmod 600 token
spatial serve compute --token-file token
NoteA worker started on the same machine measures protocol cost, not the benefit of a second machine. That benefit has not been measured yet.

Costs

CostModel estimates local cost (electricity, amortization) and cloud cost (billed hour, minimum billing, egress). Every cloud line is labelled estimated=True: prices are unverified list values and cloud speed is assumed.

EnergyThe Mac's battery gauge stayed frozen at 32.5 W between idle and full load: per-run energy cannot be measured with it. It needs powermetrics (administrator) or a power meter.
