Roadmap and open tests

What is built, what needs hardware, and what needs people. Every item not yet tested is listed with how to run it.

Built and measured on one machine

Planner (one objective, estimate against reality), console (accounts, organizations and roles, two-factor sign-in, API keys, jobs, usage, tax, numbered invoices with PDF, REST API), remote desktop for four Linux apps, fleet (agent, hub, fair share, gangs, affinity, persistence, failover, dashboard, alerts), accelerator fabric (CPU, Metal), portable kernels (incl. ARM64 via emulation), virtual interconnect, compute, tiered memory, runtime (micro-VM, WASM, Wine), security hardening.

Needs hardware

ItemWhy it matters
An NVIDIA GPURun the generated CUDA C and the numba.cuda path; price a GPU as a planner option. Decides whether the commercial thesis holds.
Two or more real machinesAgents on real hosts, all-reduce on a real network, per-node speed instead of an assumption
A power meter (sudo powermetrics)Energy per run is estimated today, not measured
An AMD GPUCompile and run the generated HIP source
CXL, RDMA, Apple SiliconStudied on paper or tested once

Needs people or accounts

  • Independent security review of the SWP/2 protocol and an adversarial test of the micro-VM sandbox.
  • A billed cloud run, to compare the planner's dollar estimate with an invoice.
  • Conversations with GPU cloud and inference operators, then a design-partner pilot with a measured saving.
  • Patent, trademark and export-control checks.

Not built

  • A Windows VM route (no licence); remote desktop beyond three Linux apps (audio, clipboard policy, several users); comparisons with Docker Desktop, UTM, Parallels, CrossOver.
  • Model routing, vLLM or llm-d, and GPU inference (a real small model was measured on the CPU: prefix reuse saved at least ×41 on a 946-token prompt, identical answers).
  • A replicated log for the hub, tiling and tensor cores in kernels, coverage-guided fuzzing.

The full list with identifiers and procedures: docs/TESTS_NOT_DONE.md and ROADMAP.md in the repository. A weekly workflow (verify.yml) re-checks the properties behind the published results.
