API REST

Tout ce que fait la console, pour les scripts.

L'API REST de la console est celle que la console utilise elle-même. URL de base : votre console (par exemple http://127.0.0.1:8090). Corps et réponses en JSON. Erreurs : {"error": "message"} avec le statut HTTP (400 entrée invalide, 401 non connecté, 402 budget atteint, 403 refusé, 404 introuvable ou pas à vous, 409 conflit, 429 trop de tentatives).

Authentification

  • Session de navigateur : POST /api/login pose un cookie HttpOnly ; envoyez la valeur csrf renvoyée dans un en-tête X-CSRF-Token sur chaque POST, PATCH et DELETE.
  • Jeton de compte (scripts) : créez-en un dans Settings, puis Authorization: Bearer spt_…. Pas de cookie, pas de CSRF. Un jeton read ne peut que faire des GET. Les jetons ne peuvent ni créer de jeton, ni changer le mot de passe, ni supprimer le compte, ni lister les sessions.
curl -H "Authorization: Bearer $TOKEN" http://127.0.0.1:8090/api/apps
curl -X POST -H "Authorization: Bearer $WRITE_TOKEN" -H "Content-Type: application/json" \
     -d '{"name":"batch"}' http://127.0.0.1:8090/api/apps

Organisations, pagination, limites

  • Tout agit dans une organisation : votre espace personnel par défaut, ou celle désignée par l'en-tête X-Org: <id> (ou ?org=<id> pour les liens simples comme le PDF). Pas membre : 404.
  • Les listes (apps, jetons, sessions, activité, utilisateurs admin) acceptent limit (100 par défaut, 500 au plus) et offset et répondent {"…": [...], "total": n, "limit": l, "offset": o}.
  • Limites de débit : 600 requêtes par minute et par utilisateur connecté, 120 par jeton (429 au-delà).

Exemple : de rien à un résultat

# avec un jeton write
APP=$(curl -s -X POST -H "Authorization: Bearer $T" -H "Content-Type: application/json" -d '{"name":"demo"}' $BASE/api/apps | jq .app.id)
curl -s -X POST -H "Authorization: Bearer $T" -H "Content-Type: application/json" -d '{"name":"n","kind":"node"}' $BASE/api/apps/$APP/keys | jq -r .key.token > node.tok
spatial agent --hub HUB:7700 --token-file node.tok &
curl -s -X POST -H "Authorization: Bearer $T" -H "Content-Type: application/json" \
     -d '{"workload":"montecarlo_pi","params":{"samples":1000000}}' $BASE/api/apps/$APP/jobs
LimitesPas de pagination ni de webhooks vers vous (l'usage s'interroge), pas de limite de débit par jeton, une surface d'API non versionnée susceptible de changer. Testée via HTTP dans tests/test_platform.py.
