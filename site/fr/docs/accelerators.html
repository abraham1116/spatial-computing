Accélérateurs et noyaux

Un travail, décrit une fois, placé sur le périphérique le moins cher : CPU, GPU Metal, GPU NVIDIA ou nœud distant. Les noyaux s'écrivent une fois et sont générés pour chaque périphérique.

PérimètreLe CPU et le GPU Metal sont testés sur un Mac. Les sources NVIDIA (C CUDA) et AMD (HIP) sont générées, jamais compilées, jamais exécutées : cette machine n'a aucun de ces GPU.

Ce que ce n'est pas

  • Pas de l'émulation CUDA. La licence de NVIDIA interdit les couches de traduction qui exécutent du code CUDA sur un autre matériel. Nous ne traduisons ni ne réimplémentons CUDA. ZLUDA (Apache-2.0/MIT) a été étudié et non utilisé : il demande un GPU AMD, que cette machine n'a pas, et il résout un autre problème (exécuter ailleurs des binaires CUDA existants).
  • Pas un remplaçant de l'orchestration NVIDIA (KAI/Run:ai, Dynamo) : elle est open source ; nous nous y branchons au lieu de la concurrencer.

Le fabric

Chaque périphérique exécute sa propre implémentation native du même travail. Le planificateur sonde chacune sur des tailles réduites, vérifie qu'elles s'accordent, et choisit la moins chère pour la taille réelle.

Noyaux portables

Un noyau est un sous-ensemble typé de Python (int, float32, boucles, branches, sin, sqrt…). La même source donne du code CPU, du code Metal et une source CUDA/HIP. Le code non pris en charge est refusé avec un numéro de ligne.

from spatial.kernel import kernel

@kernel
def collatz(i: int, j: int, n: int, limit: int):
    x = i * n + j + 1
    k = 0
    while x != 1 and k < limit:
        if x % 2 == 0:
            x = x // 2
        else:
            x = 3 * x + 1
        k += 1
    return k

collatz.run("metal", 512, limit=1000)        # table n x n
collatz.reduce("metal", 512, limit=1000)     # somme sur la grille, en mémoire partagée
print(collatz.to_cuda_c(), collatz.to_hip())

Mesuré (MacBook Pro 2017, Intel Iris Plus 640)

Limites

Deux formes de noyau (table 2-D, somme de toute la grille). Pas de tuilage, de cœurs tenseurs ni d'autres réductions. Le travail est modélisé en n² : les noyaux dépendants des données ne sont que grossièrement proportionnels. Détails : docs/KERNELS.md, docs/FABRIC.md.
