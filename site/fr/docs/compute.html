Compute Engine

Détecte le matériel, mesure son usage, compare des stratégies d'exécution et choisit la meilleure.

Détecter et surveiller

spatial audit lit le matériel réel (modèle, cœurs, jeu d'instructions SIMD, GPU, RAM, swap, stockage) et l'état courant : pression mémoire, taux du compresseur de macOS, ressources inactives, puis liste les limites qui en découlent.

Comparer des stratégies

Le ComputeScheduler exécute chaque stratégie d'un calcul de référence, mesure durée, temps CPU et mémoire de pointe, et rejette tout résultat différent de la référence. Stratégies fournies pour la charge de démonstration : Python pur, NumPy, Numba JIT, Numba multi-fils, pool de processus à froid et à chaud, worker distant, distribué local + worker.

from spatial.compute import detect_node
from spatial.compute.scheduler import ComputeScheduler

sched = ComputeScheduler(detect_node())
rows = sched.compare("exp", {"n": 4000, "iters": 300}, sched.mandel_strategies())
best = sched.choose(rows, objective="time")   # "time" | "cpu" | "energy"

Déporter vers un worker

Le worker n'exécute que des charges nommées dans une liste blanche : aucun code n'est transmis. Il écoute sur 127.0.0.1 et exige un jeton (HMAC).

python3 -c "import os;open('token','wb').write(os.urandom(32))" && chmod 600 token
spatial serve compute --token-file token
À savoirUn worker lancé sur la même machine mesure le coût du protocole, pas le gain d'une seconde machine. Ce gain n'a pas encore été mesuré.

Coûts

CostModel estime le coût local (électricité, amortissement) et cloud (heure facturée, facturation minimale, sortie réseau). Toute ligne cloud est étiquetée estimated=True : les prix sont des valeurs de liste non revérifiées et la vitesse cloud est supposée.

ÉnergieLa jauge de batterie du Mac est restée figée à 32,5 W entre repos et pleine charge : l'énergie par exécution n'est pas mesurable avec elle. Il faut powermetrics (administrateur) ou un wattmètre.
